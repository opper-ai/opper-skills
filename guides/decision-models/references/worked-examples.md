# Worked examples: three games, three questions

Real requests, generated by each game's own code (October 2026), and what changing them did. Read them for the shape and the reasoning, not to copy: your game's facts are different.

## Snake: facts, never the answer (a benchmark)

Source: [opper-ai/decision-benchmarks, games/snake](https://github.com/opper-ai/decision-benchmarks/tree/main/games/snake). One `choice` per step, 275 ms a step, real time.

```json
{
  "model": "typesafe/jev-1.13.0",
  "state": {
    "board": [
      "##################",
      "#................#",
      "#................#",
      "#................#",
      "#.............tnH#",
      "#................#",
      "#................#",
      "#................#",
      "#................#",
      "#................#",
      "#................#",
      "#................#",
      "#................#",
      "#...........A....#",
      "#................#",
      "#................#",
      "#................#",
      "##################"
    ],
    "length": 3,
    "apple": "9 down and 4 left of the head",
    "stepsSinceApple": 11,
    "step": 11
  },
  "questions": {
    "snake": {
      "type": "choice",
      "instructions": "You steer a snake on a 16 by 16 board, one cell per step. Pick the direction the head moves next (it cannot reverse). Eating the apple scores 1 and makes the snake one longer. The game ends when the head leaves the board or runs into the snake (the tail cell is free: the tail moves on this step), after 150 steps without an apple, or after 1000 steps. The board, top row first: # wall, H head, n neck (the body cell joined to the head), o body, t tail, A apple, . empty. Up is toward the top row. Eat as many apples as you can.",
      "criteria": {
        "up": "Go up: Next cell: empty. Distance to the apple after the move: 14. Cells reachable from there: 253 (the snake is 3 long after the move).",
        "down": "Go down: Next cell: empty. Distance to the apple after the move: 12. Cells reachable from there: 253 (the snake is 3 long after the move).",
        "right": "Go right: Next cell: the wall. The game ends."
      }
    }
  }
}
```

What is deliberate here:

- **The deadly move is offered** and says plainly that it ends the game. Nothing is labelled safe or best. No move is ever played for the model.
- **Absolute directions, shuffled.** Version 2 asked `left / straight / right` relative to the heading in a fixed order: "Clef answered 'left' on almost every step, Kev and Laya walked straight into walls." Version 3 keys options by `up / right / down / left` (never the reverse), and shuffles them from a hash of the step, the head and the apple, so the bench, the page and the server's request check all build the identical question.
- **No `heading` field.** With one, "Aplomb answered the current heading ('straight' on) on 46 of 51 and 53 of 60 steps and ran into the wall"; without it, 15 to 18 apples. The heading is readable from the board: the neck `n` is the body cell behind the head.
- **The apple in board terms** ("9 down and 4 left of the head"), so no model counts cells.
- **Precomputed, not decided:** the distance after the move and the reachable area (a flood fill). Those two facts are enough for a flood-fill script to score 48.85 apples, level with the best model (48.8). For a benchmark that is the warning sign: the question's facts almost carry the decision, and models that use them well score near the script.
- **The fallback never helps:** straight unless deadly, else the first non-deadly turn. It never steers toward the apple.

Results (100 games each, ± 2 standard errors where shown): GPT-6 Luna 48.8 ± 2.3, Jev 37.9, Aplomb 25.1, Microsoft Decision 1 20.1 (41% late steps), Clef Flash 9.9, Clef 7.0, Kev 6.7, Laya 0.34. Baselines: flood 48.85, greedy 29.3, random 0.45.

## JevMan: hand the model what code knows (a game first)

Source: [opper-ai/jevman-benchmark](https://github.com/opper-ai/jevman-benchmark), `src/brain.ts` and `src/features.ts`. Pac-Man asks about the next junction as soon as it commits to a corridor; the ghosts can be models too, each with a persona.

```json
{
  "pacman": {
    "type": "choice",
    "instructions": "You are Pac-Man. Clear the maze by eating every pellet while staying away from the ghosts; touching a non-frightened ghost costs a life. Power pellets (o) make ghosts frightened and edible, so take one when ghosts are closing in. Never pick a route marked DANGER or TRAP unless every route is; prefer routes where ghosts are moving away. A cherry worth 100 points (as much as 10 pellets) is on the board and will disappear soon. One route is marked FRUIT: it is the fastest way to it that looks safe. Take the FRUIT route. You are approaching junction (12,11) heading down. Pick the direction to take there.",
    "criteria": {
      "up": "Go up: nearest pellet 3 steps away; 3 pellets in the next corridor; nearest dangerous ghost 9 steps away, coming toward you; DANGER: Pinky in this corridor; TRAP: Pinky can reach the next junction in 0 steps, you need 15; power pellet 28 steps away",
      "left": "Go left: nearest pellet 16 steps away; 0 pellets in the next corridor; nearest dangerous ghost 8 steps away, coming toward you; TRAP: Blinky can reach the next junction in 2 steps, you need 12; power pellet 23 steps away",
      "right": "Go right: FRUIT — fastest safe-looking way to the cherry (17 steps, worth 100 points); nearest pellet 6 steps away; 0 pellets in the next corridor; nearest dangerous ghost 16 steps away, coming toward you; you reach the next junction in 9 steps, 2 steps before any ghost; power pellet 22 steps away"
    }
  }
}
```

The state beside it is the maze as text rows with a legend (`# wall, . pellet, o power pellet, F fruit, P Pac-Man, B Blinky, K Pinky, I Inky, C Clyde (lowercase = frightened, edible), e eyes`), the positions as numbers, mode, lives, score and the fruit's seconds left. A request with four questions (Pac-Man plus ghosts) is about 5 KB.

What is deliberate here:

- **The verdict is computed and named.** "Spelling out one safe, reachable fruit route works far better than per-route distances: jev weighed 'cherry 14 steps away' against pellets and mostly let the fruit expire." When the fruit can't be reached safely, the instructions say so: "ignore it". On the leaderboard Jev eats most of the fruit it sees.
- **Loud tags, named in the instructions:** `DANGER` (a ghost in the corridor), `TRAP` (a ghost reaches the next junction first), `FRUIT`. The precomputation that matters is the race to the junction: a test notes that without the trap check "left (pellet 1 step away) would beat right".
- **Facts for when Pac-Man acts:** distances count his walk to the junction, and the fruit route uses a conservative speed so the fruit is still there on arrival.
- **Instructions change with the mode:** frightened ghosts ("Hunt the nearest frightened ghost if you can reach it in time"), each ghost's persona ("You are Clyde... within 8 tiles you lose your nerve"), scatter time.
- **A second, separate question** (`pacman_escape`: keep going or turn back now) only when a ghost blocks the corridor ahead, once per situation.
- **What JevMan gave up for honesty:** a safety re-check at the moment of acting "roughly doubled how long jev Pac-Man survives", and it was removed so that "every move is the model's own". Its ghost questions still include each route's distance to the ghost's goal, so the ghosts measure partly how well a model follows given facts. Fine for a game; know it when you read the leaderboard.

Results (100 games each): Jev 2,750, GPT-6 Luna 2,568, Clef Flash 2,538, Clef 2,476, Microsoft Decision 1 2,390, Aplomb 1,693, Kev 1,506, Laya 639 (its 512-token context is shorter than one question). A die roll scores 1,037. A chat model through the adapter (Qwen 3.8 27B): 2,321 at $0.065 a game, ten times Jev's cost.

## Jev Fighter: when the options gave the answer away

Source: [opper-ai/decision-benchmarks, games/fighter](https://github.com/opper-ai/decision-benchmarks/tree/main/games/fighter), especially `docs/specs/2026-10-06-v2-harness.md`. A 2D fighting game at 60 frames a second; a fighter is asked ahead of the frame it can act on.

Version 1 had four independent reviews. Their findings: "the option facts handed models the answer (a text parser beat every model 132-0)", a knocked-down fighter could never defend, the second mover always won, "real time mostly measured latency", "the greedy fallback played for slow models", and the sample was too small to rank anything. Version 2 rebuilt the question on two tracks.

**Raw track** (the benchmark): the situation and the rules, each option a move's static facts.

```json
{
  "state": {
    "you": "100 HP, meter 0, standing, free to act, 0.7 from your wall",
    "opponent": "100 HP, meter 0, standing, free to act, 6.3 from their wall",
    "distance": "2.0",
    "time": "round 1, 60 s left, rounds won 0-0",
    "recent": "none yet"
  },
  "questions": {
    "move": {
      "type": "choice",
      "instructions": "You control one fighter in a 2D fighting game. Win the round with more HP than the opponent when time runs out, or by knocking them out. Strikes beat throws, throws beat blocks, blocks beat strikes (a blocked strike does 1/4 damage). ... Each option gives the move's height, damage, startup and recovery frames, and reach in body-lengths. Probabilities, when asked for: how likely each move is to be your best choice.",
      "criteria": {
        "jump": "airborne 34f, dodges lows and throws",
        "dash_forward": "forward 0.8 in 9f",
        "block_high": "stops highs and jump kicks",
        "backdash": "back 1.0, untouchable 6f",
        "walk_forward": "forward 0.4 in 12f",
        "block_low": "stops lows",
        "walk_back": "back 0.4 in 12f, guards high",
        "jump_kick": "overhead, 10 dmg, startup 13f, recovery 14f, reach 2.0, jumps in, must be blocked high"
      }
    }
  }
}
```

**Assisted track** (same state): each option is a payoff row simulated by the engine, several numbers so none reads as the answer.

```json
"criteria": {
  "jump": "avg 0, worst 0; adv -35f, ends 2.0",
  "dash_forward": "avg -0.8, worst -9 (if sweep); adv -10f, ends 1.2; then sweep avg +6.6",
  "block_high": "avg 0, worst 0; adv -18f",
  "walk_forward": "avg -0.1, worst -2 (if jump_kick); adv -13f, ends 1.6; then jump_kick avg +1.3",
  "jump_kick": "avg -1.4, worst -14 (if uppercut); adv -35f"
}
```

(`avg`: HP swing averaged over the opponent's plausible replies; `worst`: its best reply, named; `adv`: frame advantage when it ends; `then`: what a movement sets up.)

What is deliberate here:

- **Only reachable attacks are offered**; the order is shuffled per question, seeded and recorded.
- **Fair perception:** the opponent is shown as it was 10 ticks (167 ms) ago, about human reaction time. Fast moves can't be reacted to; slow ones can.
- **Token budget:** raw about 350 tokens, assisted about 550; short-context models get compact rules, then lose columns, then history, then the weakest options. State lines are capped at 240 characters, options at 160.
- **The benchmark plays raw, live:** "No payoff rows: the model works out what wins." The baselines play the same raw question and work the payoffs out themselves, so a model is measured against what the rules allow, not against hints.
- **The fallback blocks high.** "The harness never plays well on a model's behalf."
- **Timing bugs looked like model weakness.** Refreshing a question every time the fight moved starved models: "GPT-6 Luna got 1 answer played in a whole match against greedy". Now one question is in flight; an answer plays on the first frame its fighter can act, if still legal, else the fallback; only a new round drops a question in flight.
- **Baselines must think as slowly as models.** Instant bots ranked maximin 71.2, greedy 54.2, payoff 24.5; with 250 ms of thinking (15 frames) the order flipped to payoff 76.6, greedy 67.3, maximin 40.4.
